# AML Prefilter Research Summary

This repository preserves the AML prefilter experiments and integration contract
needed to reproduce the plaintext filtering stage before expensive FHE inference.
Large raw datasets, trained model artifacts, encryption keys, and generated feature
tables are intentionally excluded.

## What This Archive Contains

- Source code for the FHE-AML pipeline under `src/`.
- Reproducible prefilter scripts under `scripts/`, including:
  - `filter_xgb.py`: pandas-based sender-side XGBoost experiments for HI-Small and HI-Medium.
  - `filter_scale_sender_only.py`: memory-lean sender-side XGBoost experiments for HI-Medium and HI-Large.
  - `analyze_same_amount_bins.py`: bucket analysis for repeated-amount features.
  - `filter_flag_table.py` and `snapshot_inference_flags.py`: inference-flag table export utilities.
- Configuration files under `configs/`.
- Unit tests under `tests/`.
- Public-safe examples under `examples/`, including a sample inference-flag table.
- Documentation under `docs/`, including the handoff contract for downstream PRISM ingestion.

## What Is Intentionally Excluded

- Raw IBM AML transaction files, pattern files, and Kaggle archives.
- Generated parquet feature matrices.
- Trained model files such as `*.joblib`, `*.pkl`, `*.json` model dumps, and ONNX exports.
- FHE keys, signing keys, PEM files, and local encryption artifacts.
- Local run logs, caches, notebook scratch work, and machine-specific paths.
- PR worktrees and external repositories used only for comparison or integration exploration.

These files are excluded because they are either too large for source control,
regenerated by the documented commands, or potentially sensitive.

## Main Experimental Setting

The prefilter is evaluated as a high-recall transaction filter. A threshold is
selected on the validation set to retain a target fraction of illicit
transactions, then applied once to the test set. The main operating point is
95% illicit retention.

The strongest compact feature direction is based on repeated amount behavior,
sender history, counterparty history, and a 12-hour causal activity decay. This
keeps the feature set small while preserving most of the gain from larger
feature sets.

### HI-Large

The memory-lean script was used for HI-Large to avoid materializing the full
pandas feature pipeline. The best overall ranking quality came from adding
receiver-bank and role-ratio context while keeping sender-side transaction
decisions.

| Feature set | History mode | Features | Test rows | Test illicit | Actual retained @95 target | Dropped | ROC-AUC | PR-AUC | Runtime |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|
| mainline_decay12h | bank_local | 18 | 35,924,723 | 47,388 | 94.8% | 92.5% | 0.989 | 0.475 | 20.8 min |
| mainline_flow_amounts | bank_local | 24 | 35,924,723 | 47,388 | 94.8% | 92.5% | 0.989 | 0.481 | 28.8 min |
| mainline_receiver_bank_role | strict_sender | 30 | 35,924,723 | 47,388 | 96.4% | 91.2% | 0.990 | 0.520 | 27.2 min |

For model comparison and feature exploration it is useful to inspect both:

- validation-selected thresholds, which match deployable evaluation discipline;
- test-calibrated thresholds, which are diagnostic only and should not be used as
  the headline result.

At a diagnostic test-calibrated 95% actual retention, `mainline_receiver_bank_role`
reaches about 92.4% dropped on HI-Large, while `mainline_decay12h` reaches about
92.2% dropped.

## Reproduction Commands

HI-Small and HI-Medium:

```bash
python scripts/filter_xgb.py \
  data/HI-Small_Trans.csv \
  data/HI-Small_Patterns.txt \
  --feature-set compact_core_same_amount_spread_decay12h \
  --metrics-json artifacts/feature_sets/hi_small_compact_decay12h_metrics.json
```

HI-Large:

```bash
python scripts/filter_scale_sender_only.py \
  data/HI-Large_Trans.csv \
  data/HI-Large_Patterns.txt \
  --feature-set mainline_receiver_bank_role \
  --history-mode strict_sender \
  --metrics-json artifacts/feature_sets/hi_large_mainline_receiver_bank_role_metrics.json
```

Inference-flag export:

```bash
python scripts/filter_flag_table.py \
  --input data/transactions.csv \
  --output examples/inference_flags_sample.csv \
  --meta-output examples/inference_flags_sample.meta.json
```

The sample export format is documented in
[`docs/inference-flag-table.md`](inference-flag-table.md).
